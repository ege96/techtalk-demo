# Recipe search, three ways (pgvector demo)

The demo for the Team K tech talk **"Beyond Ctrl+F: Semantic Search with pgvector"**. It searches 30 short recipes with keyword search (Postgres full-text), semantic search (pgvector) and hybrid search (both, fused with Reciprocal Rank Fusion), and shows the three result lists side by side.

The steps below follow appendix slides A1–A6, so anyone can rebuild the demo after the talk at their own pace.

```
recipes.csv ──> load.py ──> Postgres + pgvector ──> app.py ──> search page
 30 recipes     embeds each   text, tsvector and     FastAPI     same query,
                recipe once   vector in one table    /search     3 columns
```

## What's in this folder

| File | What it does | Slide |
|---|---|---|
| `compose.yaml` | Optional one-command Postgres + pgvector (also runs `schema.sql`) | A1 |
| `schema.sql` | The `recipes` table, HNSW + GIN indexes | A2 |
| `recipes.csv` | 30 recipes, with near-misses on purpose | A2 |
| `load.py` | Embeds every recipe once and inserts it | A3 |
| `hybrid.sql` | Slide 13's hybrid query, in psycopg's `%(name)s` style | 13, A4 |
| `app.py` | FastAPI `/search?q=...&mode=keyword\|semantic\|hybrid`, plus the page at `/` | A4 |
| `index.html` | The side-by-side search page | 9 |
| `warm_up.py` | Downloads the model ahead of time and checks it | Before class |
| `check_queries.py` | Prints every mode's results for your demo queries | Before class |
| `requirements.txt` | Python packages | A1 |

## You need

- Docker Desktop (or Docker Engine), running.
- Python 3.10 or newer.
- Internet the first time, for `pip install` and the model download (about 90 MB). After that, everything runs offline.

---

## Step 1 (A1): Start Postgres with pgvector

The `pgvector/pgvector` image is the official Postgres image with the extension already built in.

**Option A, as on the slide:**

```bash
docker run -d --name pgv -e POSTGRES_PASSWORD=pw -p 5432:5432 pgvector/pgvector:pg17
docker exec -it pgv psql -U postgres -c "CREATE DATABASE demo;"
```

**Option B, one command:** `docker compose up -d`. This creates the `demo` database and runs `schema.sql` for you, so you can skip step 3. Use A or B, not both (they both name the container `pgv`).

The password `pw` is for a local demo only.

Port 5432 already taken (for example by a local Postgres)? Use `-p 5433:5432` (or change it in `compose.yaml`) and set `DB_URL` in step 2.

## Step 2 (A1): Python environment

macOS / Linux:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`sentence-transformers` pulls in PyTorch, so the first install takes a few minutes. On Linux without a GPU, install the much smaller CPU build first: `pip install torch --index-url https://download.pytorch.org/whl/cpu`.

If you changed the port in step 1, point the scripts at it:

```bash
export DB_URL=postgresql://postgres:pw@localhost:5433/demo      # macOS / Linux
$env:DB_URL = "postgresql://postgres:pw@localhost:5433/demo"    # PowerShell
```

## Step 3 (A2): Create the table

Skip this if you used `docker compose`.

```bash
docker exec -i pgv psql -U postgres -d demo < schema.sql
```

PowerShell doesn't support `<`, so use:

```powershell
Get-Content schema.sql | docker exec -i pgv psql -U postgres -d demo
```

The `tsv` column is generated by Postgres from title + description, so you never fill it yourself. The `embedding` column is `vector(384)` because all-MiniLM-L6-v2 outputs 384 numbers.

## Step 4 (A3): Embed and load the recipes

```bash
python warm_up.py   # downloads the model once and prints "Model ready: 384 numbers, length 1.000"
python load.py      # prints "Loaded 30 recipes, 384 numbers each."
```

`load.py` embeds `"<title>. <description>"` for every row with `normalize_embeddings=True` (length 1, so cosine distance and inner product rank the same way). It empties the table first, so running it again is safe.

## Step 5 (A4, A5): Run the search API

```bash
uvicorn app:app --reload
```

Open <http://localhost:8000> for the side-by-side page, or <http://localhost:8000/docs> to try `/search` directly. From a second terminal:

```bash
curl "localhost:8000/search?q=a+quick+dinner+without+meat&mode=keyword"
curl "localhost:8000/search?q=a+quick+dinner+without+meat&mode=semantic"
curl "localhost:8000/search?q=dal+bhat&mode=keyword"
curl "localhost:8000/search?q=dal+bhat&mode=semantic"
curl "localhost:8000/search?q=dal+bhat&mode=hybrid"
```

In Windows PowerShell 5, `curl` is an alias for something else, so type `curl.exe`.

Each call returns a JSON list of up to 5 recipe titles. Keyword search finds the recipe that contains every query word, so "a quick dinner without meat" returns only Quick Meat Sauce Pasta. Semantic search ranks by meaning. Hybrid adds `1 / (60 + rank)` from each list.

## Step 6: Try your own queries

```bash
python check_queries.py "vegetarian comfort food" "lentils" "something sweet to bake"
```

Good tests are a synonym the text never uses, a misspelling, and a very specific name. Together they show where each mode is strong.

## Before class (presenters)

Do this on the laptop you'll present from, the day before and again an hour before.

1. Docker Desktop is running and `docker ps` shows `pgv`.
2. Run `python warm_up.py` once with internet. The model is now in the local Hugging Face cache.
3. Turn on offline mode in the terminal you'll demo from, so a bad classroom network can't stall the model load:
   - macOS / Linux: `export HF_HUB_OFFLINE=1`
   - PowerShell: `$env:HF_HUB_OFFLINE = "1"`
4. Run `python load.py`, then `python check_queries.py`. **Copy the real results into slides 10–12.** The slide results are placeholders and may not match what MiniLM returns.
5. Start `uvicorn app:app` (no `--reload` needed in class), open <http://localhost:8000>, and zoom the browser to 150%.
6. Keep slides 10 and 11 (with your real results) as the backup if anything fails live.

**If something fails during the talk:** the page shows "Error: HTTP 500" when Postgres is down. Run `docker start pgv`, then restart uvicorn (the app opens its database connection once, at startup). If the model can't load, uvicorn won't start; check `HF_HUB_OFFLINE` was set only *after* `warm_up.py` succeeded. Either way, switch to the backup slides and keep going.

## Troubleshooting (A6)

| You see | Fix |
|---|---|
| `type "vector" does not exist` | Run `CREATE EXTENSION vector;` inside the `demo` database, not `postgres` |
| `expected 384 dimensions, not 768` | The model and the column disagree: change `vector(N)` or the model |
| Semantic results look random | Same model and `normalize_embeddings=True` on both sides (`load.py` and `app.py`) |
| `Connection refused` | Check `docker ps`, the port, and `DB_URL` |
| `The '<' operator is reserved` | PowerShell: use the `Get-Content ... \|` form in step 3 |
| `relation "recipes" does not exist` | Run step 3 (or `docker compose down -v && docker compose up -d`) |
| `OSError: We couldn't connect to 'https://huggingface.co'` | First run needs internet; run `warm_up.py` online before setting `HF_HUB_OFFLINE` |
| `422 Unprocessable Entity` | `mode` must be `keyword`, `semantic` or `hybrid` |

Reset everything: `docker rm -f pgv` (or `docker compose down -v`), then start again at step 1.

## Small differences from the slides

The code matches appendix A3/A4, with these additions to make it safer to run live:

- `load.py` runs `TRUNCATE recipes RESTART IDENTITY` first, so running it twice doesn't duplicate rows.
- `DB_URL` can be overridden with an environment variable (for the port-taken case).
- `app.py` types `mode` as `Literal[...]`, so a wrong mode gives a clear 422 instead of a 500, and it serves `index.html` at `/`.
- `hybrid.sql` is slide 13's query with `$1` → `%(v)s` and `$2` → `%(q)s`.

## Going further

- **Other languages.** all-MiniLM-L6-v2 is English-focused. A multilingual model such as `intfloat/multilingual-e5-small` also outputs 384 numbers, so the schema stays the same, but E5 expects `"query: "` in front of queries and `"passage: "` in front of documents. Change the model name in `load.py`, `app.py` and `warm_up.py`, add the prefixes, and reload.
- **Filters.** Add a `WHERE` clause (for example a `vegetarian boolean` column) to any of the three queries. It's plain SQL.
- **Bigger data.** With thousands of rows the HNSW index starts to matter. Check it is used with `EXPLAIN ANALYZE` on the semantic query.
